# Авторизация и синхронизация прогресса

## Принцип

Пользователь опознаётся по Telegram ID (`tg_<chatId>`). Доступ даёт белый список
`allowed_users.json`. Внутри Telegram пароль не нужен: Mini App присылает `initData`,
подписанные ключом бота, и сервер проверяет подпись — подделать чужой ID нельзя.
Пароль нужен только для входа из обычного браузера, где подписи нет.

## Потоки входа

### Mini App (Telegram)

1. Показывается заглушка «Идёт проверка доступа».
2. Если в localStorage есть токен сессии → `GET /api/me`, при успехе сразу в приложение.
3. Иначе `POST /api/auth/telegram` с `initData`.
4. Сервер проверяет HMAC-подпись и возраст `auth_date` (не старше суток).
5. Подпись верна и ID в белом списке → сессия и вход.
6. Подпись верна, но ID не в списке → экран пароля.

### Браузер

1. Та же заглушка, `initData` нет.
2. Есть сохранённый токен → `GET /api/me` → вход.
3. Нет → экран «Нужен доступ»: поле пароля и кнопка «Запросить пароль».
4. Кнопка ведёт в бота с `/start password` — админу приходит заявка.
5. Админ выдаёт код: `/password <chatId>` → пользователю приходит код на 30 минут.
6. `POST /api/auth/password` → код гасится, ID попадает в белый список, выдаётся сессия.

### Офлайн-сборка

`dist/index.html` открывается через `file://`. Там `isOfflineBuild === true`,
авторизация и синхронизация пропускаются целиком, прогресс живёт в localStorage —
поведение как до появления аккаунтов.

## API

Слушает `127.0.0.1:8790`, наружу проксирует nginx по пути `/api/`.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/auth/telegram` | вход по подписанным `initData` |
| POST | `/api/auth/password` | вход по одноразовому коду |
| POST | `/api/auth/logout` | погасить сессию |
| GET | `/api/me` | проверка живости сессии |
| GET | `/api/progress` | прогресс и настройки показа |
| PUT | `/api/progress` | сохранить прогресс |
| GET | `/api/health` | статус сервиса |

Сессия — случайный токен на 180 дней в заголовке `Authorization: Bearer`.

## Команды бота

| Команда | Кто | Действие |
|---|---|---|
| `/start` | все | приветствие и кнопка открытия приложения |
| `/start password` | все | заявка админу на доступ |
| `/id` | все | показать свой chat id |
| `/password <id>` | админ | выдать одноразовый код на 30 минут |
| `/grant <id>` | админ | выдать доступ сразу, без кода |
| `/users` | админ | список тех, у кого есть доступ |
| `/revoke <id>` | админ | отозвать доступ и все сессии |

## Хранение

Данные лежат **вне** git-репозитория, поэтому `git pull` их не трогает:

```
/mnt/different-project/mnemo-data/
  allowed_users.json     кто имеет доступ
  passwords.json         активные одноразовые коды
  sessions.json          токены сессий
  progress/tg_<id>.json  прогресс по словам и настройки показа
/mnt/different-project/mnemo-env/
  .env                   BOT_TOKEN и ADMIN_CHAT_ID (в git не попадает)
```

Запись идёт через временный файл с переименованием — обрыв не оставит битый JSON.

## Синхронизация прогресса

- При старте `hydrateFromServer()` заливает серверный прогресс до первой отрисовки.
- Каждое сохранение прогресса или настроек ставит отправку с задержкой 1.5 с,
  чтобы серия ответов внутри урока ушла одним запросом.
- `visibilitychange` и `pagehide` досылают несохранённое при уходе со страницы.
- localStorage остаётся: он и кеш, и запасной вариант, если сервер недоступен.
